# MEIS 信创环境：现用组件与国产小改平替

> **用途**：说明当前生产/实施需安装的基础组件，以及在信创（信息技术应用创新）要求下、**改动尽量小**的国产平替选型。  
> **原则**：优先「同协议 / 同方言」替换，避免换达梦、非 Redis 协议中间件、非 S3 存储等大改路径。  
> **状态**：选型建议（非已完成兼容认证清单）。具体以院方招标/信创目录为准，落地前须专项联调与回归。

## 1. 当前标准安装栈（非信创）

现场/实施机通常需要：

| 组件 | 现行选型 | 作用 |
|------|----------|------|
| **JDK** | **17** | 运行各业务 JAR（Spring Boot 3.2） |
| **数据库** | **PostgreSQL 15** | 业务库；`public` + `tenant_{code}` Schema 多租户 |
| **缓存** | **Redis 7**（Windows 常用 **Memurai**） | 缓存等 |
| **反向代理** | **Nginx**（或 IIS 反代） | 托管前端静态资源 + `/api` 反代 |
| **对象存储** | **MinIO**（API 建议 **9100**，避开高拍仪 Eloam **9000**） | 附件上传/下载（经 `meis-file`） |

可选/按场景：Nacos（注册配置，开发可关）、NSSM（Windows 服务化）等，见部署文档。

**客户端（不在本表「服务器五件套」内，但信创常一并问）**：Web（Chrome/Edge）、Flutter App、微信小程序。

## 2. 信创是什么（简述）

信创指在关键行业用**国产软硬件与生态**满足安全可控与验收要求，常见包括：国产 OS、国产数据库、国产 JDK、国产中间件、国产浏览器等。  
**不等于**某一单一产品；以甲方目录与测评要求为准。

MEIS **当前未宣称已完成信创全栈认证**；下表为「若改造，工作量相对最小」的平替建议。

---

## 3. 国产 / 信创平替对照（改动从小到大）

| 现用 | 小改动平替（推荐序） | 预估改动量 | 说明 |
|------|----------------------|------------|------|
| **JDK 17** | ① 毕昇 JDK 17<br>② 腾讯 Kona 17<br>③ 其他 **Java 17** 国产 OpenJDK 发行版 | **极小** | 一般只改 `JAVA_HOME` / 安装包；**不可**降到 JDK 8/11（Boot 3 依赖 17） |
| **PostgreSQL 15** | ① **海量 Vastbase**（PG 兼容）<br>② **openGauss** / GaussDB（PG 血统）<br>③ **人大金仓 KingbaseES（须 PG 模式）** | **中** | 同属 PG 线，相对接近现有 SQL（UUID、JSONB、Schema 租户、Flyway）。须全量联调与回归 |
| **Redis / Memurai** | ① 继续 Redis（若院方允许开源）<br>② **兼容 Redis 协议**的国产中间件 | **极小～小** | 协议兼容则多改连接配置；非 Redis 协议则要改 Spring Data Redis 接入 |
| **Nginx** | ① 继续 Nginx（多数场景可接受）<br>② 目录内国产 Web / 反向代理 | **极小～小** | 多为站点与反代配置平移，不改业务代码 |
| **MinIO** | ① **S3 API 兼容**的国产对象存储 / 私有云 OSS<br>② 继续 MinIO（若允许开源组件） | **小** | 文件能力集中在 `meis-file`；S3 兼容优先，改 endpoint/密钥即可 |

### 3.1 不推荐作为「最小改造」的选项

| 现用 | 不推荐平替 | 原因 |
|------|------------|------|
| PostgreSQL | **达梦**（默认 Oracle 方言路径） | 方言差异大；UUID / JSONB / Schema 多租户改造重 |
| Redis | 不兼容 Redis 协议的中间件 | 需改缓存接入代码 |
| MinIO | 非 S3、私有 API 对象存储 | 需重写 `meis-file` |
| JDK 17 | 强制 JDK 8/11 国产发行版 | 与 Spring Boot 3.2 不匹配 |

## 4. 工作量最小的一套示例组合

在**院方数据库与中间件目录允许**的前提下，建议：

| 层级 | 选型 |
|------|------|
| 服务器 OS | 统信 UOS / 银河麒麟（优先 **x86_64**，暂缓鲲鹏 ARM 以降低移植成本） |
| JDK | 毕昇 JDK **17**（或同级 Java 17 国产发行版） |
| 数据库 | **海量 Vastbase**，或 openGauss，或金仓 **PG 模式**（三选一，看招标目录） |
| 缓存 | Redis 或 **Redis 协议兼容**国产件 |
| 反向代理 | Nginx（或目录指定国产反代） |
| 对象存储 | **S3 兼容**存储（或仍用 MinIO） |
| 浏览器（客户端） | 奇安信 / 360 等 Chromium 内核国产浏览器（前端抽检） |

**一句话**：`国产 x86 OS + 国产 JDK17 + PG 兼容库（海量/openGauss/金仓PG）+ Redis 兼容 + Nginx + S3 兼容存储`。

## 5. MinIO 与业务功能（为何文件存储几乎必装）

MinIO 仅被 **`meis-file`（8092）** 使用。业务统一：

- 上传：`POST /api/file/upload`
- 下载/预览：`GET /api/file/download/{object}`

| 模块 | 用到文件能力的场景 |
|------|--------------------|
| 资产 | 设备档案、证照附件、高拍仪拍照上传 |
| 采购 | 合同/注册证/验收与质检报告、议价记录、论证类附件等 |
| 维修 | 故障图片（Web / App / 小程序） |
| 运维 | 执行现场照片、手写签名图 |
| 通用 | Schema 中 `file` / `imageList` 类字段 |

未启用对象存储时：纯表单/列表多数可用；**附件与拍照类功能不可用**。

## 6. 落地前须向院方确认

1. 数据库目录是否包含 **海量 / openGauss / 金仓（PG 模式）**？若仅有达梦 → 非最小路径。  
2. 服务器 CPU：**x86** 还是鲲鹏 ARM？有 x86 则优先 x86。  
3. Redis、MinIO、Nginx 是否允许开源组件？不允许则按第 3 节选目录内兼容产品。  
4. 是否要求 **国密 TLS / 等保一体测评**？（另立项，不属于五件套平替本身。）

## 7. 粗估工作量量级（仅供排期参考）

| 项 | 量级 |
|----|------|
| OS + 国产 JDK17 + 部署脚本 | 小（约 1～2 人周） |
| PG → 海量 / openGauss / 金仓 PG 全量联调回归 | 中（约 3～6 人周，视环境与用例） |
| Redis 协议兼容 / Nginx / S3 兼容存储 | 小（多为配置与冒烟） |
| 国产浏览器抽检（列表/弹窗/打印/高拍仪） | 小（数日） |
| 达梦 + 非 S3 存储 + ARM 全栈 | 大（应拆期，不作一期最小目标） |
